## Release blockers confirmed during this audit

- The project root has no `LICENSE` file. `docs/LICENSE_DECISION_MATRIX.md` recommends keeping the repository unlicensed until the owner finalizes the commercial strategy. This is an owner decision; no license has been selected or applied, so the repository cannot yet be represented as an open-source release.
- The original numbered Markdown requirement bundle is not present in `requirements/source/`. The recovered specifications are normalized working references. The consolidated folder is present at both the AI_Workspace root and AgentForge-Staging; a fresh SHA-256 comparison on 2026-09-23 found 55 matching Markdown files in each folder (54 source documents plus the generated index). This is not the original numbered bundle, and the 54 documents mix AgentForge requirements, repository docs, Antigravity artifacts, workspace notes, and unrelated references. The complete original-to-implementation traceability pass cannot be claimed until any original numbered requirements are located and reconciled.
- The main master goal has sections 0–49 (50 sections). Other documents have independent, overlapping numbering; “38” is not a count of the master requirements or proof of 38 source files.
- Three obsolete standalone probes that claimed to verify the live OpenClaw/Telegram path were retired because their private adapter and dashboard endpoint are absent; this does not establish live integration.
- Browser smoke acceptance passed against the built local UI in an isolated in-app browser. It does not establish a full interactive workflow or live Telegram integration.

## Verified changes in this audit pass

- Completion repair no longer marks requirements implemented/tested or invents source/test paths when no repair executor ran.
- The Completion Engine has an opt-in atomic JSON session repository with restart restoration of its PRD, DAG status, and traceability records. OriginalGoal hashes are checked on load, invalid DAG/traceability state fails closed, and a persisted `COMPLETE_VERIFIED` label is downgraded until evidence is freshly revalidated. Server/API wiring and signed evidence provenance remain incomplete; see [`COMPLETION_ENGINE_TRACEABILITY.md`](COMPLETION_ENGINE_TRACEABILITY.md).
- The PRD critic no longer reports a pass when its lexical scan finds omitted goal terms or missing safety coverage; execution now remains blocked on a failed critique. The review is still heuristic, not semantic.
- The completion contract now fails when a required real-browser or provider check lacks explicit passing evidence, and task execution remains blocked when the PRD critic finds uncovered terms or missing safety requirements. Automatic semantic PRD repair is not yet implemented.
- TODO auditing now handles the marker forms named by the spec, defaults actionable source/config markers to release blockers, and avoids treating documentation, test fixtures, ordinary UI placeholder attributes, and its own marker definitions as unfinished code. A read-only whole-checkout scan found 47 markers and classified none as release blockers; this is not evidence that missing roadmap capabilities are complete. Task-scoped changed-file selection and parser-aware review remain open.
- The completion Execution DAG now validates unique requirement IDs, existing dependency targets, and acyclic relationships before replacing its current graph. Invalid candidate graphs fail closed while retaining the last known-good graph; focused tests cover missing nodes, duplicates, cycles, and retention.
- Completion checks require recent evidence files that exist inside the task workspace; missing and out-of-workspace paths fail closed.
- Unmeasured models no longer receive synthetic pass rates; benchmark rates are derived from the registered benchmark result schema.
- `/api/compute` reports missing provider and host telemetry instead of fabricated healthy RAM/sandbox values.
- Task diff/evidence routes return unavailable until an evidence pack actually exists.
- The local control plane rejects non-local `Origin` and `Host` values, including mutation attempts.
- Worktree creation uses Git directly, rejects unsafe names, and fails instead of creating a fake directory on error.
- New workspace owner sample data no longer includes prefilled Telegram/Discord identity IDs.
- Standard test runs no longer trigger paid MiMo smoke calls just because `MIMO_API_KEY` exists; live calls require `AGENTFORGE_LIVE_TESTS=1` as well. Credential cleanup now deletes absent env vars instead of assigning `undefined`.
- The AgentForge bridge no longer imports configuration code from the sibling OpenClaw repository; it accepts a local model-selection contract and reads only non-secret AgentForge model selectors.
- The vNext `/api/route` endpoint validates request fields and rejects malformed requests with HTTP 400 instead of trusting an unchecked cast.
- The packaged CLI no longer reports a false `ready` status. Package test execution now explicitly reports that it is unimplemented instead of fabricating four passing checks, and the package benchmark measures local manifest validation instead of returning a hard-coded latency and score.
- Fixed strict-type and correctness issues across the entire source tree, including broker routing, benchmark examples, the exported metrics script, legacy smoke fixtures, and error handling. The previous 130 whole-source TypeScript diagnostics are now zero.
- Broker optimization now awaits the asynchronous optimizer; lab simulation and its callers await routing rather than silently treating a Promise as an optimization result. Embedding provider batch results now retain every returned vector and update the active dimension for real providers.
- The old OpenClaw routing, repeated-context, and Telegram-handler probes were unsafe evidence: they referenced a machine-specific private adapter and a dashboard route that no longer exist. They were replaced with explicit retired-probe notices, and the package no longer advertises the OpenClaw routing probe as a supported smoke command.
- CLI smoke response parsing now validates unknown error payloads safely rather than relying on unchecked property access.
- Markdown consolidation is repeatable with `pnpm docs:collect`; external artifacts can be passed explicitly, preserved on future runs, and filename collisions are rejected instead of silently overwriting a document. Canonical source files stay in place.
- Provider readiness, tester instructions, migration acceptance language, storage status, and visible UI claims were corrected to distinguish local implementation from live or production evidence. JSON persistence was wired into launcher startup; focused restart/recovery tests and a running-server HTTP restart test pass. Built-dist and cross-platform durability acceptance remain open.
- Telegram mirroring no longer silently maps unlinked external IDs to the workspace owner. Privileged commands and approval callbacks fail closed; task-control and approval decisions check explicit user permissions and audit denial. Fake `/compute`, `/diff`, `/evidence`, and `/ask` success claims were replaced with current capability/evidence reporting. Focused mirror, migration, and adversarial tests pass; Web/API authentication remains open.
- A supported local Telegram owner-link flow is now wired through Settings and the canonical mirror router: it issues a ten-minute single-use code, rejects redemption from group chats, links the Telegram identity durably on private-chat redemption, and rejects replays or identities already linked elsewhere. This is tested through the local Telegram adapter only; no real Telegram bot was configured or contacted.
- The vNext UI no longer presents seeded agent/task entries as active work or claims live Telegram/Discord sync, test success, model prices, verified publishers, or production actions. Marketplace, approvals, voice simulation, and migration fixture screens are labeled with their actual local/mock boundaries. Dynamic workspace and package text is HTML-escaped before rendering.
- Browser acceptance caught a JavaScript parse error in approval buttons that prevented the entire navigation script from loading. The escaping was corrected and a test now compiles the complete inline browser script before accepting the rendered UI.
- Package starter generation rejects unsafe names, defaults all permissions off, and marks the starter unlicensed until its author chooses a license. CLI validation now includes lifecycle-script and path-traversal checks; package test execution remains unavailable and is reported honestly.
- Marketplace manifest validation now rejects malformed untrusted runtime objects without throwing, validates permission subfields and publisher/capability/dependency/pricing shapes, blocks duplicate capability/dependency IDs and Windows device names, and validates traversal by path segment. `agentforge pack inspect-archive <package-directory> <archive.zip>` checks bounded ZIP contents in memory without writing files; it rejects symlinks and other special file types, executable modes, duplicate/unsafe paths, unsupported compression, ZIP64/malformed extras, header mismatches, overlapping records, malformed deflate streams, CRC mismatch, oversized expansion declarations and high expansion ratios, and checks the package file list against the manifest. It is not wired to package installation. Focused tests cover malformed roots, safe `..` inside filenames, actual traversal segments, Windows reserved names, ZIP64 extras, size mismatches, data descriptors, overlapping local records, valid deflate, CRC corruption, symlinks, duplicate paths, executable modes, oversized entries, and inventory mismatch.
- GitHub Actions CI now uses the checked-in pnpm lockfile and Node 22/24 across Windows, Ubuntu, and macOS. Each matrix job performs strict typecheck, full tests, build, launcher-restart persistence acceptance, and package CLI acceptance with no live credentials. Hosted results remain pending a push or pull-request run.
- The local process watchdog no longer defaults into the OpenClaw production checkout or log directory, and it no longer selects/kills an arbitrary Node server. Its default target is the AgentForge staging vNext entry point, and process termination is restricted to a command line matching that absolute entry path. The script explicitly reports Windows-only support.
- The Pi, Pydantic, and AgentForge Native harness fixtures now fail task execution by default and explicitly report that no task ran; deterministic fake success is available only through test-only simulation opt-in. Advertised runtime/tool/MCP capabilities are disabled until real adapters exist.
- The local HTTP API caps request bodies at 8 MiB and returns HTTP 400 for malformed/non-object JSON or HTTP 413 for oversized payloads. End-to-end tests exercise all three rejection cases.
- Agent and task creation now validate bounded fields and enum values, reject duplicate IDs and missing assignees, and only allow new tasks in `backlog` or `ready`. New tasks receive a restricted contract; supplied contracts with any enabled execution authority are rejected until the executor can enforce those grants. IDs are generated safely, and the create-agent UI no longer turns names into IDs or advertises enabled tools/auto-resume by default. Tests cover these API boundaries.
- Scribe process diffs now align unchanged steps, classify edits separately from additions/deletions, preserve the source URI during comparison, report only newly introduced unresolved review rules, and reject comparisons above a bounded step-cell limit. The UI stages an updated SOP as a durable proposal, displays the diff, and requires explicit approval before activating it; rejection leaves the active version alone, stale proposals fail closed, and older snapshots can be restored as new revisions. Revision history and proposals persist in canonical workspace snapshots. Tests cover proposal persistence, approve/reject/stale behavior, UI rendering, oversized input, rollback, and restart round-trip. Authenticated reviewer identity and affected-agent revalidation remain open.
- Process compilation now always returns a typed contract template and cannot let an unrelated or already-resolved rule on a privileged step suppress the explicit authorization blocker. The generated contract disables all authority flags, including outbound network, and requires human approval when blockers exist; an adversarial regression test covers the suppression case.
- Tiered local model routing now discovers installed Ollama models instead of returning hardcoded model IDs. It avoids unverified local routing for vision, tool-calling, and structured-output requests, and `forceLocalOnly` now errors rather than silently selecting a remote provider when no suitable local model is available.
- OpenAI-compatible chat completions now forward tools, tool choice, JSON response mode, and stop sequences; non-streaming and streamed tool-call deltas are returned in the provider contract with stable IDs. It no longer invents costs for arbitrary compatible endpoints; usage records token counts and leaves cost unknown without model-specific pricing evidence. Offline stubbed-fetch tests cover both paths; no live API request was made.
- Execution contract path checks now reject traversal embedded under an otherwise allowed prefix (for example `src/../../outside.ts`). Shell command checks enforce the explicit delete-files, outbound-network (including ordinary Git push/fetch/pull/clone), force-push, and deployment gates for recognized command patterns; adversarial tests cover these denials and an allowed outbound request. Policy errors omit the full command text to avoid echoing embedded secrets. This is an additional fail-closed layer only: shell syntax can obscure effects, and no real worker or OS sandbox consumes the contract yet.
- When the caller supplies the isolated workspace root, execution-contract path validation canonicalizes the target and its nearest existing ancestor and rejects symlink escapes. A real temporary-directory adversarial test covers a symlink from an allowed `src/` folder to an outside directory. Callers that omit the workspace root still receive lexical scope checks only; the worker must pass its managed worktree root before this can protect a real run.
