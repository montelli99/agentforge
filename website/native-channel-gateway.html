What native messaging connections does

The native gateway starts and stops configured adapters. Telegram uses a BotFather token and polling; Discord uses its Gateway; Slack uses Socket Mode. Optional compatibility relays are separate paths.

Use it in your workflow

Connect one service at a time. Check gateway status, then check actual inbound and outbound behavior. Keep a single polling owner for a Telegram bot and test in an isolated conversation.

A practical example

Illustrative workflow

You can run the local workspace with Telegram while leaving Discord and Slack unconfigured. Their credentials are independent.

What to verify

Check the records associated with this workflow, not just the final chat response. Confirm the project, selected configuration and expected output agree. If a provider is involved, validate a real request in your own deployment before treating it as connected.

Current boundaries

A ready status is one diagnostic signal, not end-to-end proof. A channel still needs correct permissions, bindings and authorization.

Implementation reference

This guide describes the current public implementation. Developers can inspect docs/NATIVE_GATEWAY_OPERATIONS.md for the relevant behavior. This reference supplements the explanation above.

Configuration and operating details

The following settings and behavior apply to this workflow in the current implementation.

Runtime contract

The native gateway is exposed through NativeAgentForgeGateway and the control plane routes:

  • GET /api/gateway/status
  • POST /api/gateway/start
  • POST /api/gateway/stop

The setup guide's GET /api/setup-guide/channel-runtime response includes secret-safe status for both telegramBotApi and nativeTelegramSession; it never returns a token, API hash, or session string.

The gateway starts provider adapters through the shared runtime registry, normalizes inbound events into the canonical workspace, and sends outbound messages through the provider-neutral channel contract. A runtime being started does not claim that an external provider is authenticated; each adapter must report live readiness independently.

Hierarchy and mirroring

Workspaces contain spaces, spaces may contain child spaces for departments or subgroups, and channels belong to spaces. Child spaces are created with parentSpaceId and can be queried with GET /api/spaces?...&parentSpaceId=. Provider bindings remain attached to canonical channels so Telegram topics, Discord channels, Slack threads, and the native web surface can mirror the same workspace state.

Put it into practice

Start with a clean local workspace, connect the capability you need and verify a small result before expanding your workflow.
