Your first workspace

Let the Setup Guide organize your goal, then connect the capabilities you need.

Begin with an outcome

Open the local application and describe a small result. For example: “Help me prepare a documentation review for a small software project.” The built-in Setup Guide can organize the initial work before you connect a model.

The deterministic setup creates a private local project, a General channel, a Workspace setup conversation, an initial reviewable goal and a Setup Guide agent. It preserves the outcome you entered. This is useful organization; it is not evidence that a model has reasoned about or executed the goal.

What the guide can help with

Use the setup conversation to keep decisions together: what the project is for, who should review the result, what output is expected and which capabilities are still missing. Once a chat provider is configured, the conversation can request natural-language planning help through the chosen model.

The guide does not silently import another application's credentials, connect an account or grant tools. You supply private connection settings and review the resulting scope. A role record and a connected worker are different things.

Connect a model when you want generated responses

Follow the model guide to set the dedicated credential, allowed model identifiers and optional endpoint. Restart the server. Select a configured model in the composer; Save locally stores the message without a model call.

Ask for a small checklist and verify a follow-up response. If a provider error occurs before text returns, your saved user message remains available to retry. Stop preserves a partial reply with its status. Do not interpret a saved conversation as proof that generation worked.

Design roles around real handoffs

Start with an author and a reviewer only if the task genuinely benefits from separate responsibilities. Specify what the author produces and what the reviewer checks. Add departments and subgroups when the work needs separate channels and ownership.

For the documentation example, the author prepares installation steps and the reviewer verifies them. The acceptance criterion is a newcomer reaching a working installation, not the number of pages created. Keep the decision and the evidence in the project.

Reuse a procedure

When a process already exists, bind its selected revision to the appropriate agent and prepare a task from that binding. Review unresolved rules before proceeding. Imported instructions describe a proposed process; they cannot grant themselves permission to publish, delete or access another system.

Preparation produces reviewable work. It does not start execution. A changed procedure may need a new review, especially if its required effects or output destination change.

Turn on execution deliberately

The optional approved Docker mode requires the configured repository and a ready Docker backend. Review the plan and contract before approval, then explicitly run the task. Read the observed checks and inspect the artifact before calling it complete.

For a first task, choose a disposable repository and a harmless output. If the backend reports missing capabilities, fix those capabilities rather than changing the task status to look complete.

Recognize a successful first session

  • The project retains the outcome you entered.
  • The conversation persists after a reload.
  • A configured model responds when selected.
  • Roles have clear responsibilities and bounded access.
  • Any execution attempt has real checks and an inspectable result.
  • The next step remains visible when a capability is not configured.

When setup feels stuck

Check the missing capability rather than starting another workspace. No generated answer points to model configuration. No task execution points to the backend and plan gates. No channel reply points to the transport, binding and authorization path. Each has a dedicated guide on this site.

Put it into practice

Start with a clean local workspace, connect the capability you need and verify a small result before expanding your workflow.
